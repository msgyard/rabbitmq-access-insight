What it shows

The questions an audit, a migration or an incident asks first.

Which accounts are really used?

Every account defined in the cluster next to what actually logged in: last login, sessions, time online, sources, clients.

  • Never used accounts, ready to remove.
  • Dormant ones, last seen weeks ago.
  • Accounts in use but not defined here — LDAP or OAuth 2 users.
  • Names that only ever failed, like a password-guessing run.

How does each one authenticate?

Password, token or certificate, for every session. When the authentication backend reports the credential it verified, the method is confirmed; otherwise it is inferred from the SASL mechanism, the configured backends and the user database — and labelled as such.

Sources, clients, protocols and virtual hosts per account, with a daily history.

Where do logins fail?

RabbitMQ checks a login in three steps. Each failure is recorded with the step that refused it and RabbitMQ's own reason:

  • failed — the credentials were refused;
  • refused — the credentials were fine, then authorization or the virtual host said no.

By account, source and reason, per day.

How it stays right

A history you can reconcile, not a best guess.

Each node records what happens on it. Account totals are copied to every other node, and whatever could not be recorded is shown, with its time and reason.

Restarts lose nothing

The journal is made durable every second and replayed after the last snapshot. An orderly stop loses nothing; a hard crash at most one second, and is marked.

A lost node keeps its accounts

Account totals of every node live on the others. Wipe a node's disk, or remove it from the cluster: its accounts' history is still there, until you choose to forget it.

Never counted twice

Each node writes only its own totals; copies carry versions and never move backwards. The cluster view takes exactly one copy per node.

Gaps are shown, not hidden

An unclean stop, a disk alarm, or events dropped to keep the broker fast are recorded with their time range — not smoothed over.

Measured

Cheap where it matters.

It works only when connections open and close, in its own processes, and never blocks a connection or a message.

Install

Three steps, no restart.

1

Download

The .ez for your broker's Erlang/OTP: otp25, otp26, or otp27 for OTP 27 – 29.

2

Copy

Into the plugins directory of every node.

3

Enable

On every node; it picks up connections already open.

rabbitmq-plugins enable \
  rabbitmq_access_insight
